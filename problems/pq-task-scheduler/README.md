# 작업 스케줄러 (우선순위 큐)

## 문제

CPU가 하나뿐인 서버에 `N`개의 작업이 들어온다. `i`번 작업(1부터 번호를 매긴다)은
시각 `t_i`에 도착하고, 실행에 `d_i`만큼의 시간이 걸리며, 우선순위 값 `p_i`를 가진다.
**우선순위 값이 작을수록 더 급한 작업**이다.

CPU는 시각 `0`에 비어 있고, 다음 규칙에 따라 작업을 처리한다.

1. CPU가 비어 있는 시각 `T`에, 이미 도착했지만(`t_i ≤ T`) 아직 실행되지 않은 작업 중에서 하나를 골라 즉시 실행한다.
   - 우선순위 값 `p_i`가 가장 작은 작업을 고른다.
   - 그런 작업이 여러 개면 도착 시각 `t_i`가 가장 이른 작업을 고른다.
   - 그래도 여러 개면 번호 `i`가 가장 작은 작업을 고른다.
2. 대기 중인 작업이 하나도 없으면, 다음 작업이 도착할 때까지 CPU는 쉰다.
3. 작업은 한 번 시작하면 중간에 멈추지 않고(비선점) `d_i` 동안 실행된 뒤 끝난다.
   끝나는 시각에 CPU는 다시 비게 되며, 그 시각에 도착한 작업도 선택 대상에 포함된다.

작업 `i`의 **대기 시간**은 `(실행 시작 시각) - t_i`이다.

모든 작업이 실행되는 순서와, 모든 작업의 대기 시간의 합을 구하라.

## 입력

- 첫째 줄에 작업의 수 `N`이 주어진다.
- 다음 `N`개의 줄 중 `i`번째 줄에 `t_i d_i p_i`가 공백으로 구분되어 주어진다.

## 출력

- 첫째 줄에 작업이 실행되는 순서대로 작업 번호를 공백으로 구분하여 출력한다.
- 둘째 줄에 대기 시간의 합을 출력한다.

## 제한

- `1 ≤ N ≤ 200,000`
- `0 ≤ t_i ≤ 10^9`
- `1 ≤ d_i ≤ 10^4`
- `0 ≤ p_i ≤ 10^9`
- 입력은 도착 시각 순으로 정렬되어 있지 않을 수 있다.
- 대기 시간의 합은 32비트 정수 범위를 넘을 수 있다.

## 예제 1

입력

```
4
0 3 2
1 9 1
2 6 1
3 2 0
```

출력

```
1 4 2 3
16
```

설명

| 시각 | 대기 중인 작업 `(번호: p, t)` | 선택 | 실행 구간 | 대기 시간 |
|---|---|---|---|---|
| 0 | 1: (2, 0) | 1 | [0, 3) | 0 |
| 3 | 2: (1, 1), 3: (1, 2), 4: (0, 3) | 4 | [3, 5) | 0 |
| 5 | 2: (1, 1), 3: (1, 2) | 2 | [5, 14) | 4 |
| 14 | 3: (1, 2) | 3 | [14, 20) | 12 |

대기 시간의 합은 `0 + 0 + 4 + 12 = 16`이다.

## 예제 2

입력

```
5
5 2 1
5 1 1
0 1 3
20 4 2
6 3 1
```

출력

```
3 1 2 5 4
4
```

설명

- 시각 0에 3번 작업만 도착해 있으므로 `[0, 1)` 동안 실행한다.
- 시각 1~5에는 대기 중인 작업이 없어 CPU가 쉰다.
- 시각 5에 1번, 2번 작업이 모두 `p = 1, t = 5`이므로 번호가 작은 1번을 `[5, 7)` 동안 실행한다.
- 시각 7에 2번 `(1, 5)`, 5번 `(1, 6)` 중 도착이 이른 2번을 `[7, 8)` 동안 실행한다. (대기 2)
- 시각 8에 5번을 `[8, 11)` 동안 실행한다. (대기 2)
- 시각 11~20에는 CPU가 쉬고, 시각 20에 4번을 `[20, 24)` 동안 실행한다.

대기 시간의 합은 `0 + 0 + 2 + 2 + 0 = 4`이다.

## 힌트

<details>
<summary>힌트 1</summary>

매번 "도착한 작업 전체"를 훑어 최솟값을 찾으면 `O(N^2)`이 되어 `N = 200,000`에서 시간 초과가 난다.

</details>

<details>
<summary>힌트 2</summary>

작업을 도착 시각 순으로 정렬해 두고, CPU가 비는 시각까지 도착한 작업을
`(p, t, 번호)`를 키로 하는 **최소 힙**에 넣자. 힙이 비어 있으면 현재 시각을 다음 도착 시각으로 건너뛴다.

</details>

## 풀이 요약

1. 작업 번호를 `(t, 번호)` 순으로 정렬한다.
2. `now = 0`에서 시작해 모든 작업을 처리할 때까지 반복한다.
   - 힙이 비어 있고 다음 작업이 아직 도착하지 않았다면 `now`를 그 도착 시각으로 옮긴다.
   - `t ≤ now`인 작업을 모두 힙에 `(p, t, 번호)`로 넣는다.
   - 힙에서 최솟값을 꺼내 실행한다. 대기 시간 `now - t`를 더하고 `now += d`.
3. 각 작업은 힙에 한 번 들어가고 한 번 나오므로 전체 시간 복잡도는 `O(N log N)`, 공간 복잡도는 `O(N)`이다.
